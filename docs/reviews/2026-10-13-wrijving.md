# Wrijving in sandbox, beslisroute en GitHub (2026-10-13)

Onderzoek op `origin/main` `594b101` (2026-10-13), op verzoek van de eigenaar: waarom werkt de agent niet soepel in de sandbox, is
de goedkeuring van ADR's en specs slim ingericht, en hoe verbeteren de processen richting GitHub. Geen besluit; de maatregelen
staan als losse PR's of als voorstel.

## 1. Sandbox

Oorzaken, gemeten in een sandbox-sessie op deze repo:

| # | Oorzaak | Gevolg | Maatregel |
|---|---|---|---|
| S-1 | `mise.toml` installeerde pnpm `11` (11.28.5), `packageManager` pint 11.28.2; een losse pnpm 12 stond eerder op `PATH` | pnpm schakelt zelf en wil een schrijfbare store: `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK`, ook in pre-commit | mise exact op `packageManager` en `check-docs` bewaakt dat (PR `chore/sandbox-pnpm-pin`); de losse pnpm van `PATH` is werk van de eigenaar |
| S-2 | `permissions.deny` `Read(./**/*secret*)` en `Read(.env.*)` worden sandbox-`denyRead`; de sandbox legt een leeg apparaatbestand over elk pad dat past | `node_modules/better-auth/dist/context/secret-utils.mjs` en `jose/.../generate_secret.js` zijn leeg: typed lint (`ensure-account.ts:43`) en `blocked.test.ts` falen alleen in de sandbox; `git` faalt op `.env.example` | `sandbox.filesystem.allowRead` voor `./node_modules` en `./.env.example` (voorstel, zie §4) |
| S-3 | Dezelfde maskering op ref-namen en bestandsnamen met `secret` | een branch `…-secrets-…` kan niet worden aangemaakt (`refs/heads/…` is een apparaatbestand); een testbestand met die naam ook niet | geen `secret` in branch- of bestandsnamen tot S-2 gedaan is |
| S-4 | Hooks draaien buiten de sandbox, de agent erbinnen | de Stop-hook meldt fouten die de agent niet kan reproduceren (lint op S-2) | volgt uit S-1 en S-2 |
| S-5 | Lokale `main` liep achter; de SessionStart-hook haalde niets op | een review concludeerde ten onrechte dat een branch actueel was (`origin/main` was 34 commits verder) | SessionStart haalt `origin/main` op en meldt de achterstand (PR `chore/session-start-fetch`) |
| S-6 | Sandbox legt dotfiles (`.bashrc`, `.gitconfig`, `.idea`, …) als maskers in de repo | vals vuil in `git status` | `.git/info/exclude` (lokaal, geen repowijziging) |

Niet veranderd: Docker en `pnpm dev` blijven van de eigenaar (framework §11). `test:db`, `ui:check` en `gate:slow` lopen volgens
ADR 0027 punt 6 via de runner zonder dev-stack; of dat in de praktijk al werkt, is niet gecontroleerd.

## 2. Beslisroute voor ADR's en specs

Gemeten via `gh pr list --state merged` (12–13 oktober 2026, 40 PR's): ongeveer vijf leveren productfunctionaliteit, de rest is
docs, hooks, rails en scripts. Een eenregelige statuswijziging via de GitHub-webeditor duurde 4 minuten (#126); de wachttijd zit in
het aantal ronden: voorstel, status en bouw zijn drie PR's voor één beslissing (ADR 0026: #115, #116, #117), plus register en
`pr:verify`. Het voorstel staat in ADR 0029 (status `voorgesteld`).

## 3. GitHub

- **G-1** De agent pusht onder het account van de eigenaar (ADR 0017, overgang); daardoor kan de eigenaar geen eigen PR formeel goedkeuren en
  eist de ruleset geen review. De GitHub App (ST-01) lost dat op; geparkeerd op 2026-10-12 (W-3). Heroverweging staat in ADR 0029 onder "Niet beslist".
- **G-2** De job `secrets` scande alle refs; één valse melding maakte elke open PR rood (bevinding 10 in `2026-10-12-werkstraat.md`).
  PR `chore/ci-scan-scope`: op een PR alleen de eigen commits, op `main` de hele geschiedenis.
- **G-3** `gh run view --log-failed` vraagt een schrijfbare cache (`XDG_CACHE_HOME`); niet opgelost, werkafspraak.

## 4. Open besluiten voor de eigenaar

1. S-2: `allowRead` toevoegen aan `.claude/settings.json`. Een agent mag zijn eigen sandbox niet verruimen (de auto-mode-classifier weigerde dat terecht); dit is een wijziging van de eigenaar.
2. S-1: eenmalig `mise install` in de checkout met de nieuwe pin, en de losse pnpm 12 van `PATH` halen.
3. G-2 bevestigen (de scan op een PR is smaller dan alle refs; de scan op `main` blijft volledig).
4. ADR 0029 beoordelen.
